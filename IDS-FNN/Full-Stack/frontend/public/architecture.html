🌐 Network Traffic

Raw packets flowing through the network are captured from the selected network interface. These packets represent real-time communication between hosts and form the input data for the IDS pipeline.

🔬 Feature Extraction (Flow Scraper)

The packet capture module groups packets into network flows (based on source IP, destination IP, ports, and protocol). From each flow, statistical features such as packet counts, durations, and byte statistics are extracted. These features represent the behavior of the traffic and are used by the machine learning model.

  • PROTOCOL – Transport protocol used (TCP, UDP, ICMP).
  • L7_PROTO – Application layer protocol (HTTP, DNS, FTP, etc.).
  • IN_BYTES – Total bytes received in the flow.
  • IN_PKTS – Number of incoming packets.
  • OUT_BYTES – Total bytes sent in the flow.
  • OUT_PKTS – Number of outgoing packets.
  • TCP_FLAGS – Combined TCP flag values observed.
  • CLIENT_TCP_FLAGS – TCP flags set by the client.
  • SERVER_TCP_FLAGS – TCP flags set by the server.
  • FLOW_DURATION_MILLISECONDS – Total duration of the flow in milliseconds.
  • DURATION_IN – Duration of incoming traffic.
  • DURATION_OUT – Duration of outgoing traffic.
  • MIN_TTL – Minimum TTL value observed.
  • MAX_TTL – Maximum TTL value observed.
  • LONGEST_FLOW_PKT – Size of the largest packet in the flow.
  • SHORTEST_FLOW_PKT – Size of the smallest packet in the flow.
  • MIN_IP_PKT_LEN – Minimum IP packet length observed.
  • MAX_IP_PKT_LEN – Maximum IP packet length observed.
  • SRC_TO_DST_SECOND_BYTES – Bytes per second from source to destination.
  • DST_TO_SRC_SECOND_BYTES – Bytes per second from destination to source.
  • RETRANSMITTED_IN_BYTES – Retransmitted incoming bytes.
  • RETRANSMITTED_IN_PKTS – Retransmitted incoming packets.
  • RETRANSMITTED_OUT_BYTES – Retransmitted outgoing bytes.
  • RETRANSMITTED_OUT_PKTS – Retransmitted outgoing packets.
  • SRC_TO_DST_AVG_THROUGHPUT – Average throughput from source to destination.
  • DST_TO_SRC_AVG_THROUGHPUT – Average throughput from destination to source.
  • NUM_PKTS_UP_TO_128_BYTES – Number of packets ≤128 bytes.
  • NUM_PKTS_128_TO_256_BYTES – Number of packets between 128–256 bytes.
  • NUM_PKTS_256_TO_512_BYTES – Number of packets between 256–512 bytes.
  • NUM_PKTS_512_TO_1024_BYTES – Number of packets between 512–1024 bytes.
  • NUM_PKTS_1024_TO_1514_BYTES – Number of packets between 1024–1514 bytes.
  • TCP_WIN_MAX_IN – Maximum TCP window size received.
  • TCP_WIN_MAX_OUT – Maximum TCP window size sent.
  • ICMP_TYPE – ICMP message type.
  • DNS_QUERY_TYPE – DNS query type (A, AAAA, MX, etc.).
  • DNS_TTL_ANSWER – TTL value in DNS response.
  • FTP_COMMAND_RET_CODE – FTP server response code.

⚙️ Feature Preprocessing

Before training a Neural Network we pre-process the data, so before giving the input for predictions, the input features should also be subjected to same pre-processing. This step includes operations such as scaling, normalization, and feature ordering to ensure consistency with the data used during model training.

Numerical Encoding

Attack labels are converted to integers (e.g., Benign = 0, DDoS = 1, …).

Remove Unrealistic Values

Extremely large values (e.g., > 10⁹) are trimmed to avoid instability.

Log Transformation

Heavy-tailed features (bytes, packets, throughput, durations) are transformed using:

log(1 + x)

to reduce skew.

Standardization (Z-score)

Continuous features are scaled:

z = (x - mean) / std

to bring them to a common scale.

Class Imbalance Handling

Dataset is highly imbalanced. Applied square-root inverse frequency weighting + normalization to balance rare and frequent classes.

Categorical Feature Normalization

Large-range features (e.g., PROTOCOL, TCP_FLAGS, ICMP_TYPE) are scaled to:

x = x / max(x)

to avoid exploding gradients.

🧠 Binary Attack Detection Model – Architecture

The binary classifier is implemented using a deep residual multi-layer perceptron (Residual MLP) designed for efficient and stable learning from tabular network features.

Input Layer

  • Takes 37 preprocessed features as input.

Hidden Layers

The model consists of multiple fully connected layers with Batch Normalization, GELU activation, and Dropout:

Layer 1 → 37 to 1024
Layer 2 → 1024 to 1024 (Residual Applied)
Layer 3 → 1024 to 512
Layer 4 → 512 to 256
Layer 5 → 256 to 128

Residual Connection

A skip connection is added between the first and second layers:

x2 = x2 + x1

This helps prevent vanishing gradients, improve training stability, and enable deeper feature learning.

Regularization & Activation

  • Batch Normalization → stabilizes training
  • Dropout (0.15) → reduces overfitting
  • GELU activation → smoother and more effective than ReLU

Output Layer

Final layer: 128 → 2 neurons. Outputs probabilities for:

  • 0 → Benign
  • 1 → Attack

✅ Normal Traffic

If the binary model classifies the flow as benign, the flow is considered normal and no further attack analysis is performed. The system continues monitoring subsequent traffic.

🔍 6-Class Attack Classification – Architecture

If a flow is classified as malicious by the binary model, it is passed to a second Residual MLP for detailed attack classification.

Input Layer

  • Takes the same 37 preprocessed features.

Hidden Layers

The model uses fully connected layers with Batch Normalization, GELU activation, and Dropout:

Layer 1 → 37 to 768
Layer 2 → 768 to 768 (Residual Applied)
Layer 3 → 768 to 512
Layer 4 → 512 to 256
Layer 5 → 256 to 128

Output Layer

Final layer: 128 → 6 neurons. Outputs one of the attack classes:

DDoS DoS Bots Brute Force Scanning Exploits

⚡ FastAPI Streaming API

The prediction results are exposed through a FastAPI streaming endpoint. This API continuously outputs analyzed network flows and detected attacks in real time, allowing other system components to consume the data.

🖥️ Node.js Backend

The Node.js backend connects to the FastAPI stream and processes the incoming IDS events. It acts as a middleware layer that manages data flow and distributes alerts to connected clients.

🔌 WebSocket Live Dashboard

Using WebSocket communication, the backend pushes IDS events instantly to connected frontend clients. This enables real-time updates without requiring repeated HTTP requests.

📊 React Frontend Dashboard

The React-based dashboard visualizes the IDS results. It displays live network activity, detected attacks, and relevant metadata, allowing users to monitor network security in real time.
